# 엔티티 명세 작성 안내

엔티티를 조회·해석·변경할 때 판단이나 조치가 달라지는 세부 기준을 명세에 담는다. 추가 설명이 필요한 개념의 파일을 `docs/ontology/<개념 이름>.md`에 두고, `ONTOLOGY.yaml`의 해당 개념에 `명세문서`로 프로젝트 루트 기준 경로를 기록한다. 파일명은 `개념[].이름`을 사용하고 에이전트 지침이나 문서 목차에도 연결한다.

작업을 시작할 때 필요한 엔티티의 명세만 먼저 읽는다. YAML에 지정된 경로가 없으면 그 개념의 기본 위치를 확인한다.

## 다룰 내용 고르기

프로젝트 자료나 실제 작업에서 엔티티에 관한 세부 기준을 발견하면, 판단이나 처리에 필요한 것만 골라 명세에 추가한다. 아래 항목은 모두 선택 가능한 예시다. 작성자는 발견한 내용에 맞게 항목을 생략하거나 합치고, 이름을 바꾸거나 예시에 없는 항목을 추가할 수 있다.

- **범위와 식별**은 무엇을 이 엔티티로 보고, 언제 같은 항목을 갱신하거나 새 항목을 만드는지 설명한다.
- **상태와 처리**는 언제 확정·완료·취소할 수 있고, 그때 무엇을 확인하거나 기록하는지 설명한다.
- **관계에 따른 조치**는 자신이나 연결된 항목이 변경·삭제될 때 함께 갱신할 기록과 보존할 이력을 설명한다.
- **값의 의미와 판단 근거**는 예정 값과 실제 값, `미확인`과 `해당 없음`처럼 헷갈리는 값을 구별한다. 어떤 자료를 근거로 판단하는지도 필요할 때 적는다.
- **작성·표시 규칙**은 제목의 정보와 순서, 본문 구성, 요약의 우선 정보와 생략 기준처럼 일관성이 필요한 항목에 둔다.

고른 내용은 짧은 Markdown 목록으로 쓴다. 상위 항목에는 주제를, 하위 항목에는 조건과 그때의 판단이나 조치를 한두 문장으로 적는다. 예외와 예시는 해당 기준 아래에 둔다.

개념·관계·소스 위치와 조회·동기화 경로는 `ONTOLOGY.yaml`에서 찾는다. DB 필드명·자료형·API 제약은 소스별 기술 문서에 두고 명세의 관련 기준에서 링크한다.

## 참여 회차 명세 예시

아래는 일정 변경 이력과 취소 이력을 보존하는 가상의 프로젝트에서 작성한 `session.md`다.

~~~markdown
# 참여 회차

- 범위와 식별
  - 일정만 바뀌면 같은 회차의 일시를 갱신하고 이전 일시를 남긴다.
  - 기존 회차와 별도로 출석을 확인하는 보강은 새 회차로 등록한다.
- 상태와 처리
  - 취소가 확정되면 회차 기록을 보존하고 조회용 일정에서 빼며 참석자에게 알린다.
- 작성·표시
  - 일정에서 찾는 회차는 `2026-04-12 — 분수 개념 복습`처럼 날짜를 먼저 쓴다.
  - 주제로 찾는 회차는 `분수 개념 복습 — 2026-04-12`처럼 주제를 먼저 쓴다.
~~~

할 일 명세에 제목 규칙이 필요하면 `보강 일정을 수강생에게 안내`처럼 행동과 대상을 드러내도록 적을 수 있다.

확인된 기준을 명세에 담고, 미정인 기준은 확인 사항으로 표시한다.
