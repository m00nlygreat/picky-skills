# Korean Verbal Script

원뜻과 화자의 말투를 유지하면서, 한 번 들어도 이해되고 소리 내어 읽기 편한 발표문으로 다듬는다.
조사와 연결어미를 먼저 보완하고, 의미나 발음이 여전히 걸리는 부분만 늘려 쓴다.

## 편집 원칙

1. **‘즉·등’ 사용을 제한한다.**
   ‘즉’으로 앞말을 되풀이하는 부분은 합친다.
   ‘등’은 범위를 전달하는 데 필요한 경우에만 남기며, 생략된 항목을 임의로 만들어 넣지 않는다.

2. **조사와 연결어미를 충분히 사용한다.**
   명사와 나열 항목 사이에 필요한 조사를 붙여 단어 사이의 관계를 분명히 한다.
   조사 보완만으로 잘 들리면 그 표현을 유지한다. ‘~별’을 일괄해서 풀어 쓰거나, 나열한 항목마다 술어를 붙여 문장을 늘리지 않는다.
   예: “지점별 전용 이메일 주소를 제공합니다” → “지점별로 전용 이메일 주소를 제공합니다”.
   예: “이전 단가, 새 단가, 변동률, 관련 인보이스를 볼 수 있습니다” → “이전 단가와 새 단가, 변동률과 관련 인보이스를 볼 수 있습니다”.
   행동을 잇는 짧은 표현은 문맥의 순서와 이유가 들리도록 보완한다.
   예: “거래 내역서를 확인해” → “거래 내역서를 확인해서”. 순서를 뜻하는 문맥에서는 “확인한 다음”처럼 쓴다.

3. **긴 문장은 술어에서 끊는다.**
   여러 술어가 이어지면 의미가 완결되는 지점에서 문장을 끝낸다.
   나눈 문장 사이의 인과관계와 조건은 유지한다.
   예: “확인했고, 분석했으며, 결론을 도출했습니다” → “확인했습니다. 이를 분석해 결론을 냈습니다”.

4. **가까운 거리의 반복어를 정리한다.**
   같은 문장이나 인접 문장에서 불필요하게 반복되는 단어를 줄인다.
   핵심 용어와 의도적인 강조는 유지하며, 같은 개념의 이름을 유의어로 계속 바꾸지 않는다.

5. **필요한 명사형 표현을 동사로 풀어 쓴다.**
   조사 보완 후에도 행동과 뜻이 잘 전달되지 않는 표현을 자연스럽게 고친다.
   예: “개선 방안에 대한 검토를 진행합니다” → “개선 방안을 검토합니다”.

6. **이미 자연스러운 구어체는 살린다.**
   이미 구어체인 원고는 발음·호흡·어순 위주로 필요한 만큼 다듬는다.
   원문의 격식과 존대 수준을 유지하고, 어미를 일괄 교체하지 않는다.
   ‘~요’, ‘사실은’, ‘여러분’을 기계적으로 추가하지 않는다.

7. **현장 용어를 우선하고 숫자·단위·약어를 읽기 쉽게 쓴다.**
   사용자가 현재 작업에서 직접 지정한 현장 용어를 우선하고, 프로젝트의 `TERMs.md`에 확인된 표현을 참고한다.
   원문의 업계 용어를 임의로 순화하지 않는다. 청중에게 낯선 전문어는 필요한 경우 처음 나올 때 짧게 풀이한다.
   용어를 바꿀 때는 뜻과 단위를 유지한다. 예를 들어 수량을 뜻하는 ‘로스량’과 비율을 뜻하는 ‘로스율’을 같은 말로 취급하지 않는다.
   숫자·단위·약어는 읽는 방법을 분명히 한다.
   수치와 단위는 원문 그대로 유지한다. 고유명사나 약어의 발음이 불확실하면 추측해 적지 않는다.

8. **낭독 기준으로 최종 점검한다.**
   의미 단위로 줄바꿈하고, 숨이 차거나 발음이 걸리는 부분을 고친다.
   사실·수치·조건·주장의 확신 정도가 원문과 같은지 확인한다.
   원문에 없는 사실이나 사례, 새로운 주장을 추가하지 않는다.

9. **발음이 뭉개지는 표현은 풀어 쓴다.**
   소리 내어 읽을 때 음절이 뭉개져 의미가 잘 전달되지 않는 표현은 조금 늘려 쓴다.
   예: “고려할” → “고려해야 하는”, “직시할” → “직시하고자 하는”.
   예시는 문맥에 맞춰 적용한다. 길게 풀면서 원문에 없던 의무나 의도를 덧붙이지 않는다.

10. **문장의 의미 덩어리를 쉼표로 구분한다.**
    한 문장 안에서 의미와 호흡이 나뉘는 지점에 쉼표를 넣어, 자연스럽게 끊어 읽도록 한다.
    하나의 덩어리로 이어 읽을 표현은 붙여 두고, 잠깐 쉬는 지점을 표시한다.
    예: “이 결과를 바탕으로 다음 단계에서 무엇을 바꿀지 말씀드리겠습니다” → “이 결과를 바탕으로, 다음 단계에서 무엇을 바꿀지 말씀드리겠습니다”.

## 프로젝트 용어사전

### 첫 사용 시 선택 기록

발표 원고를 실제로 다듬는 첫 실행에 아래 절차를 적용한다. 스킬 자체를 작성하거나 수정하는 작업에는 적용하지 않는다.
`TERMs.md`와 선택 기록은 현재 원고 작업 프로젝트의 루트에서 관리한다.

1. 프로젝트의 `AGENTS.md`에서 `korean-verbal-script`의 용어 자동 수집 설정을 확인한다.
   기존 파일 이름이 `AGENTs.md`이면 그 파일을 사용한다. 설정이 있으면 그 선택을 따르고 같은 질문을 반복하지 않는다.
2. 설정이 없으면 다음 내용을 한 번 묻는다.
   “이 프로젝트의 원고와 피드백에서 현장 용어를 자동으로 모아 TERMs.md에 기록하고, 다음 윤색에도 참고할까요? 선택은 AGENTS.md에 저장합니다.”
   선택지는 ‘자동 수집’과 ‘자동 수집 안 함’이다. 응답을 기다리는 동안 대본 윤색은 진행할 수 있다.
3. 기존 지침을 보존하면서 `AGENTS.md`의 `## korean-verbal-script` 구역에 선택을 기록한다. 파일이 없으면 생성한다.
   아래는 자동 수집에 동의한 경우의 기록 예시다.

   ```markdown
   ## korean-verbal-script

   - 용어 자동 수집: 사용
   - 용어사전: TERMs.md
   - 대본을 다듬기 전에 기존 용어사전을 읽는다. 자동 수집이 ‘사용’일 때 원고와 사용자 피드백의 용어를 수집하고 갱신한다.
   ```

   ‘자동 수집 안 함’을 선택하면 ‘사용 안 함’, 응답이 없으면 ‘보류’로 기록한다. 보류는 동의로 해석하지 않으며 자동 수집도 진행하지 않는다.
   이후 답변이 도착하거나 사용자가 선택을 바꾸면 해당 기록을 갱신한다.

### 참조와 갱신

- 윤색 전에 기존 `TERMs.md`를 읽고, 용어의 사용 맥락과 확인 상태를 함께 살핀다. 자동 수집을 사용하지 않아도 기존 사전은 참고한다.
- 자동 수집이 ‘사용’이면 `TERMs.md`가 없을 때 생성하고, 현재 원고와 사용자 피드백에서 프로젝트의 업무 용어와 선호 표현을 수집한다.
- 새 사전은 다음 표로 시작한다. 기존 사전이 있으면 형식과 내용을 보존하면서 필요한 항목만 추가하거나 갱신한다.

  ```markdown
  # 프로젝트 용어사전

  | 원문·별칭 | 현장 선호어 | 의미·단위 | 사용 맥락 | 상태·확인 근거 |
  | --- | --- | --- | --- | --- |
  ```

- 사용자가 직접 지정한 선호어는 확인된 표현으로 기록한다. 원고에서 수집했거나 모델이 제안한 용어는 후보로 기록하며, 윤색 결과에 썼다는 이유만으로 확정하지 않는다.
- 용어의 선호와 뜻·단위의 확인 상태를 구분한다. 사용자가 ‘로스율’을 선호하더라도 원고가 수량을 말하는지 비율을 말하는지 불분명하면, 그 적용 조건을 확인 필요로 남긴다.
- 먼저 윤색본을 완성한 뒤, 의미나 적용이 불확실한 용어만 모아서 한 번에 확인한다. 확인할 용어가 없으면 추가 질문을 하지 않는다.
- 사용자 피드백을 받으면 자동 수집 설정에 따라 해당 항목을 갱신하고 다음 윤색부터 반영한다. 자동 수집이 ‘사용 안 함’ 또는 ‘보류’이면 사용자의 명시적인 갱신 요청이 있을 때만 사전을 생성·수정한다.

## 처리와 출력

- 원문이 문어체인지 이미 자연스러운 구어체인지 살핀 뒤, 위 원칙을 필요한 부분에 적용한다.
- 청중, 발표 자리, 원하는 말투가 주어지면 반영한다. 별도 요청이 없으면 원문의 말투를 기준으로 삼는다.
- 원고의 내용 순서와 슬라이드 구분을 유지하면서 문장과 호흡을 다듬는다.
- 기본 출력은 수정한 대본이다. 변경 이유나 전후 비교는 사용자가 요청한 경우에 덧붙인다.
- 용어 자동 수집의 첫 사용 질문과 윤색 후 필요한 용어 확인은 위 절차에 따라 별도로 안내한다.
- 사용자가 지정한 출력 형식을 따른다.
